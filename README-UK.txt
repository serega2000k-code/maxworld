MAXWORLD — серверні акаунти, збереження прогресу, монети та магазин

Структура:
- server.js — HTTP-сервер та API гри
- public/index.html — 3D-місто, персонаж, збирання монет, профіль, магазин, будинок
- package.json — запуск і драйвер PostgreSQL

Що реалізовано в цій версії:
- серверна реєстрація та вхід; паролі зберігаються у вигляді scrypt-хешу, а не відкритим текстом;
- сесійний токен для API та роль розробника, яку можна отримати лише через секретний код DEVELOPER_CODE під час реєстрації;
- збереження ігрового стану на сервері: монети, XP, рівень, професія, покращення, будинок, інвентар і меблі;
- збір монет з серверною перевіркою, щоб одну й ту саму монету не можна було повторно зарахувати тому самому акаунту;
- серверна перевірка цін і балансу під час купівлі предметів;
- API кабінету розробника для додавання тестових монет;
- PostgreSQL через DATABASE_URL. Якщо DATABASE_URL не задано, використовується серверний data.json як fallback.

Розгортання на Render:
- Root Directory: mw (або корінь архіву, якщо завантажив вміст папки mw у корінь репозиторію)
- Build Command: npm install
- Start Command: npm start
- Environment: DATABASE_URL = Internal Database URL вашої PostgreSQL бази;
- Environment: DEVELOPER_CODE = довгий секретний код, який не можна публікувати;
- Не додавай DEVELOPER_CODE у код HTML або відкритий репозиторій.

ВАЖЛИВО:
- Для збереження даних після перезапуску Render необхідно підключити PostgreSQL через DATABASE_URL. Файловий fallback потрібен лише для тестування і може втратити дані після перезапуску/перерозгортання.
- Сесії зберігаються в пам’яті процесу, тому після перезапуску сервера потрібно увійти знову; ігровий прогрес у PostgreSQL лишається.
- Це наступний робочий етап, а не завершена MMO: синхронізація руху інших гравців, повноцінна система будівництва/власності, платежі та модерація ще потребують окремої реалізації.
